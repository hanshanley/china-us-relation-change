### Same-name profiles can outlast a U.S. license

Hearst's own statement says it announced termination of its Cosmopolitan and
Esquire China licenses in November2023. Both current Sina profiles still use
the brands and official-magazine tags. We record Hearst's position without
purporting to adjudicate the underlying dispute or infer renewal from those
nominal tags.

The registry therefore treats both as historical and specifies an exclusive
Asia/Shanghai `attribution_end` of November1,2023. This conservative collection
boundary excludes the announced termination month onward; it is **not** an
assertion of the exact contractual termination day. Only earlier archive posts
are eligible. TechCrunch's documented 2013-2019 partner relationship similarly
has an exclusive January1,2020 cutoff.

The common normalizer applies these cutoffs to live feeds, archives and
authorized imports, including resumed feeds. This protects against later
same-name posts as well as obvious renamed UIDs. Existing databases migrate
without losing identities or posts; old registry records default to an
unestablished cutoff. Reports, account exports and assessment maps expose the
recorded limits.

## Retrieval improvements that enabled real evidence

Older CNET/ZDNet publisher captures declare `gb2312` but use GBK-family
characters. The bounded public client now honors HTTP-declared encoding,
then HTML metadata, including the [HTML-standard GBK-family decoder mapping](https://encoding.spec.whatwg.org/#gbk).
It does not silently replace unreadable characters. This recovered actual
publisher account links that an unconditional UTF-8 decode had rejected.
Locally retained HTML is decoded text saved as UTF-8, not a byte-for-byte
copy of the original HTTP representation.

Some exact archived originals contain the ordinary HTTP default port `:80`.
The archive adapter preserves those indexed originals and accepts only
scheme-appropriate default ports; it does not invent a new capture timestamp
by rewriting to a different archived URL.

Both live and archive collection now validate the publisher profile name.
Archives additionally accept explicitly reviewed historical outlet aliases.
An unchanged UID with a rebranded publisher is not sufficient. All thirteen
previously collected archive sources still passed this stricter check, and
the new Engadget sources passed it before import.
Real later CNET and ZDNet captures were also tested: both had the expected
UID but a different publisher name, and both were rejected without adding
their current local-brand posts to the U.S. historical-brand corpus.
